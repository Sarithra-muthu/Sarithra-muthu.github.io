flagship build

AI Test Suite Auditor

A deployed, multi-user application that audits requirements and test cases for gaps, duplicates and ambiguities, and builds a requirements traceability matrix. Built and evaluated end to end as my capstone on the 100x Engineers Applied GenAI programme.

From messy inputs to reviewable findings

Agentic system · Capstone

Problem

Reviewing test cases written by people or LLMs means catching wrong expected results, duplicates, unsupported assumptions and requirement ambiguities, then tracing tests back to requirements. A model that does this has to be trusted, which means every claim it makes must be checkable.

Approach

Three separate LLM stages with typed outputs, so one failing stage never hides the others. A deterministic check, with no second LLM, rejects any finding that cites a test that doesn't exist or quotes text that isn't in the source. A human reviewer then accepts or rejects each finding, and every decision is stored.

Built for production, not just a demo

Production-lite

Typed contracts

Every stage returns Pydantic models against a strict JSON schema at low temperature, so malformed output fails loudly instead of flowing downstream.

Failure handling

Retries and timeouts per stage. Each package finishes as complete, partial or failed, so a partial result is clearly labelled and still useful.

Audit trail

Reviewer decisions are written to an append-only table, so what was accepted, rejected and by whom can always be reconstructed.

Access control

bcrypt-hashed passwords with server-side access checks, so users only see their own packages.

Automated tests

About 20 pytest cases cover validation and access rules.

Evaluated, not just demoed

Pilot evaluation

Design

14 requirement and test packages: 4 for development and 10 held out. Three conditions: human only, auditor only, and human plus auditor. Output was frozen at a tagged commit before scoring against a draft reference key of 29 issues.

What I learned

Reviewers agreed with 23 of 26 auditor findings. Precision was 91% with findings only but 50% when the model also asked clarification questions, so I removed the questions. None of the conditions found the seven boundary-value gaps, which is a real limit of the approach.

How I build

Start from the business problem

I define what "good" looks like and how it will be measured before choosing a model or a pattern.

Verify with code, not another model

Where a claim can be checked deterministically, such as a citation or a quote, I check it in code.

Human in the loop by design

The model drafts and detects; a domain expert approves. Reviewer decisions are recorded.

Evaluate on held-out data

I compare against human baselines, freeze outputs before scoring and report the limits.

Cost and model fit

The right model for each task, with prompt trimming and context management as standard practice.
